WHAT YOU JUST SAW

NTFS wrote the times of a file into two attributes. Normal use changed only the first. A timestomping tool also changed only the first, because the function that Windows offers for setting times does not reach the second.

The result is a record that disagrees with itself: a created time in $STANDARD_INFORMATION that is older than the created time in $FILE_NAME, on an exact second, beside an MFT modified time that is recent. Windows shows the false date, and the record shows the mismatch. It is a strong lead and not a proof, because honest programs also set old dates and because a later rename can make the two sets agree.
