WHAT YOU JUST SAW

The same picture was carved twice. Stored in one run, it came back as its own six clusters, and its hash value matched. Stored in two runs, it came back as eight clusters: the tool reached the end of the first run and read straight on, through two clusters of another file, until it met the footer.

The tool reported a complete JPEG both times. In the second case the file is too long by exactly two clusters, it is damaged from the fourth cluster onwards, and its hash value does not match. The record that listed the two runs was the only thing that knew where the picture continued. This is why you never report a carved file as recovered until you have tested it.
