S03-D1: Carving by header and footer

What this shows: a carving tool reads raw bytes in order, starts a file at a header, and ends it at the footer, or at the size limit when no footer comes.

RAW BYTES OF THE IMAGE, IN ORDER. NO FILE SYSTEM IS USED.

FILES THE TOOL HAS WRITTEN

Keyboard: the left and right arrow keys move between steps.

WHAT YOU JUST SAW

The tool read the bytes in order and asked no file system for help. It started a file at each header, FF D8 FF. For the first picture it met the footer, FF D9, and stopped there: that file is exact. For the second picture no footer came, because the end of the picture had been overwritten. The tool went on until its size limit and took 8 bytes of another file with it.

Both results are files with no name and no date, called after the position where they were found. Only one of them is the picture that was once stored. The tool reports both in the same way, so you must test each carved file, and a hash value is the test.
